Neural Network Architectures — Why Each One Exists

Not a list of models. A chain of problems. Each architecture here was invented because the previous one failed at something specific — this guide names that failure, shows it, and shows the fix.

The whole chain in one picture

1. The Perceptron — 1958

The idea

One neuron. Take the inputs, weight them, add them up, and if the total clears a threshold, fire a 1; otherwise a 0. It draws a single straight line through your data and calls one side "yes" and the other side "no".

output = step(x₁w₁ + x₂w₂ + ... + b)      step(z) = 1 if z > 0 else 0

How it works

You already wrote this. It's X @ W + b from the notebook, with a hard threshold instead of softmax, and one output instead of ten. Learning rule: show it an example; if it's wrong, nudge the weights toward the right answer. Repeat.

✗ The wall: it can only draw ONE straight line

A perceptron's decision boundary is a line (a plane in higher dimensions). So it can only solve problems where a single straight line separates the classes — "linearly separable" problems.

AND is linearly separable. OR is linearly separable. XOR is not. And no amount of training fixes this — it isn't a tuning problem or a data problem, it's a geometric impossibility. There is no line. Look:

Why this mattered so much: the first AI winter

In 1969 Minsky and Papert published exactly this argument in a book. The field had been promised thinking machines; it turned out the flagship model couldn't compute a function a child understands. Funding collapsed. Neural network research went dormant for roughly fifteen years. The irony: the fix — stack another layer — was already known. Nobody could train the stacked version yet. That's what took until 1986.

✓ The fix → Multi-Layer Perceptron

Add a hidden layer with a nonlinearity. One line can't carve XOR — but two lines plus a way to combine them can. The hidden layer draws several lines; the output layer combines them into a region. The missing piece was backprop: a way to work out how to adjust the hidden weights when you only observe error at the output.

2. Multi-Layer Perceptron (MLP) — backprop, 1986

Perceptron—can't do XOR→MLP

The idea

Stack perceptrons into layers, put a bend between them, and train the whole thing with backprop. This is the network you built from scratch in the notebook.

How it works

Z1 = X  @ W1 + b1     # linear
A1 = relu(Z1)         # the bend  <-- without this the whole net collapses to one line
Z2 = A1 @ W2 + b2     # linear
A2 = softmax(Z2)      # probabilities

The bend is everything. relu(z) = max(0, z) is what makes stacking meaningful: without a nonlinearity, (X @ W1) @ W2 is algebraically just X @ W3 — one line again, and your "deep" net is a perceptron in an expensive coat.

Run the proof yourself. Exercise 1 in your notebook: delete the relu and retrain. Accuracy collapses toward the logistic-regression baseline. That's this paragraph, measured on your own machine.

How a hidden layer beats XOR

The Universal Approximation Theorem — and the trap in it

An MLP with one hidden layer can approximate any continuous function, to any accuracy, given enough hidden neurons. This is proven. It sounds like the end of the story.

It is not, and here's the trap: the theorem says such a network exists. It does not say gradient descent can find it, or that you have enough data to pin it down, or that "enough neurons" isn't an absurd number. Every architecture after this point exists because "possible in theory" and "trainable in practice" are completely different claims. Keep this distinction; it explains the rest of the guide.

✗ The wall: images break it — three separate ways

1. Parameter explosion

An MLP connects every input to every neuron. On your 8×8 digits that's fine. Scale up and it detonates:

2. Flattening destroys space

X.reshape(-1) unrolls the 8×8 grid into 64 numbers in a line. Pixel 0 and pixel 8 are vertically adjacent in the image — after flattening the network has no way to know that. Every spatial relationship is deleted before the model sees the data, and the model must rediscover neighbourhood from scratch, from examples. You felt this in Part 1 of the notebook.

3. No translation invariance

Shift a digit one pixel right. To your eye: same digit. To the flattened vector: every single number moved to a different position — a totally different input. The MLP has to learn "a 7 in the top-left" and "a 7 in the centre" as two unrelated facts. It memorises positions instead of shapes.

✓ The fix → CNN

Stop connecting everything to everything. Use a small window that slides across the image reusing the same weights. That one change fixes all three walls at once: far fewer parameters (weights are shared), space is preserved (the window is 2D), and translation invariance comes free (the same detector runs at every position).

3. Convolutional Neural Network (CNN) — 1989, and then 2012

MLP—150M params, no spatial sense→CNN

The idea

An edge is an edge wherever it appears. So don't learn a separate detector per position — learn one detector and slide it everywhere.

How it works

A kernel (say 3×3 = 9 weights) slides across the image. At each stop it multiplies its 9 weights by the 9 pixels under it, sums, and writes one number. The output is a feature map: "where in this image did my pattern appear?"

The hierarchy — the part that feels like magic but isn't

Stack convolutions and something remarkable falls out for free:

Layer 1
edges, blobs, colour patches
Layer 2–3
corners, curves, textures — combinations of edges
Layer 5+
eyes, wheels, faces — combinations of parts

Nobody programmed this hierarchy. It emerges because each layer can only combine what the layer below found. This is representation learning — the model inventing its own features — and it's the reason deep learning displaced hand-crafted feature engineering. Compare with your House Prices work, where you designed the features by hand. Here the network designs them.

Pooling

Between convolutions you usually shrink the map — MaxPool2d(2) keeps the strongest value in each 2×2 block. Halves the resolution, keeps "was the feature there?", drops "exactly which pixel". Fewer computations and a bit more shift-tolerance.

nn.Conv2d(1, 32, 3)   # 32 different 3×3 detectors
nn.ReLU()
nn.MaxPool2d(2)       # halve the resolution
nn.Conv2d(32, 64, 3)  # combine those into richer patterns
nn.ReLU()
nn.MaxPool2d(2)
nn.Flatten()          # only NOW flatten — after space has been used
nn.Linear(...)        # the MLP you already know, on learned features
Read that last block carefully. A CNN ends with an MLP. The convolutions are a learned feature extractor bolted in front of the network you already built. You haven't left the notebook behind — you've given it better input.

✗ The wall: deeper stopped helping — and then actively hurt

CNNs work, so the obvious move is more layers. From 2012 to 2015 everyone stacked deeper, and it worked — up to about 20 layers. Then it broke.

A 56-layer plain CNN performed worse than a 20-layer one — on the training set. Read that again: worse on training data. This is not overfitting (that's bad test, good train). This is a degradation problem: the deeper network couldn't even fit data the shallower one fit fine.

Which is absurd, because a 56-layer net can always simulate the 20-layer one — just make the extra 36 layers do nothing. So a solution provably exists, and gradient descent could not find it. (That Universal Approximation trap, biting for real.) The cause: gradients shrink as they're multiplied back through dozens of layers, so early layers receive almost no signal and barely train.

✓ The fix → ResNet (skip connections)

If the problem is that "do nothing" is hard to learn, then make "do nothing" the default.

4. ResNet — 2015

Deep CNN—56 layers worse than 20→ResNet

The idea

Add a shortcut that skips over each block and adds the input straight to the output:

output = F(x) + x        # instead of  output = F(x)

Now the block only has to learn the residual — the difference from its input, hence the name. If a layer is useless, it can output zeros and x passes through untouched. Doing nothing became the easy default instead of a thing to learn.

Remember this trick — it comes back. "Add a path the gradient can travel without being multiplied" is the same idea the LSTM uses for time, and skip connections live inside every Transformer block too. One idea, three architectures.

✗ The wall: a CNN has no memory and no sense of order

CNNs assume the input is a fixed-size grid where nearby means related. That's true of images. It's false of language.

Sentences are variable length, and meaning depends on order over distance:

"the movie was not good"        → negative
"not bad, the movie was good"   → positive

Nearly identical bags of words, opposite meanings. And in "The cat that the dog chased was black", "cat" and "black" are far apart but bound together. A CNN's little window sees a few words at a time and has no state that carries forward. It cannot remember.

✓ The fix → RNN

Give the network a memory: a hidden state that gets passed from step to step. Read the sequence one item at a time, updating that state. Now the network's answer at word 10 can depend on word 1.

5. Recurrent Neural Network (RNN) — 1986

CNN—no memory, fixed size→RNN

The idea

A loop. Feed in one item, update a hidden state, feed in the next item along with that state. The state is the network's running memory of everything so far.

hₜ = tanh(xₜ @ Wₓ + hₜ₋₁ @ Wₕ + b)     # new state = f(new input, old state)
yₜ = hₜ @ Wₙ + bₙ

Same weights at every timestep — weight sharing again, but across time instead of space. That's why it handles any sequence length: 5 words or 500, it's the same W applied repeatedly.

✗ The wall: the vanishing gradient — memory decays exponentially

To train across time, backprop must travel backwards through every timestep, and at each step it gets multiplied by the same weight matrix. Multiply a number smaller than 1 by itself repeatedly and it races to zero.

Concretely: tanh's derivative is at most 1 and typically ~0.5 or less. Over 20 timesteps you're multiplying ~20 such factors together:

The mirror problem: exploding gradients

If the repeated factor is above 1, the same maths runs the other way: 1.5²⁰ ≈ 3,300 and your loss goes nan. This one is easy to patch — gradient clipping (cap the gradient's magnitude, clip_grad_norm_ in PyTorch) — which is why exploding gradients are a footnote and vanishing gradients rewrote the field. You can cap a number that's too big. You cannot recover information from a number that's already zero.

✓ The fix → LSTM

Build a path through time where the gradient is added, not multiplied. Same trick as ResNet's +x, one year earlier and applied to time instead of depth.

6. LSTM & GRU — 1997

RNN—memory dies after ~15 steps→LSTM

The idea

Long Short-Term Memory. Add a second track — the cell state — that runs straight through time with only additions on it, and put small learned gates in charge of what gets written, erased, and read.

How it works — three gates

Forget gate
"what should I drop from memory?" — new subject arrives, drop the old one
Input gate
"what's worth storing from right now?"
Output gate
"what part of memory is relevant to this step?"

Each gate is a tiny sigmoid layer producing numbers in 0–1, multiplied against the memory — 0 means "block", 1 means "let through". The gates are learned, not designed. The network works out for itself what's worth remembering.

GRU (2014) is the same idea with two gates instead of three and no separate cell state. Fewer parameters, trains faster, usually performs about the same. Try both; keep the winner. Simpler is a feature.

✗ The wall: irreducibly sequential — and the bottleneck

1. You cannot parallelise time. hₜ needs hₜ₋₁. To process a 1,000-word document you must take 1,000 steps in order. A GPU has thousands of cores sitting idle while your LSTM crawls one word at a time. As datasets grew to internet scale, this became the binding constraint — not accuracy, but wall-clock time.

2. Long-range is better, not solved. Information still degrades over hundreds of steps. Word 1 influencing word 500 remains a stretch.

3. The seq2seq bottleneck. Translating a sentence meant cramming the entire source into one fixed-size vector, then decoding from it. That vector is a chokepoint — long sentences don't fit through it, and quality falls off a cliff with length.

✓ The fix → Attention, then the Transformer

Attention (2014) began as a patch for problem 3: instead of one summary vector, let the decoder look back at every source word and weight what's relevant. It worked so well that in 2017 someone asked the obvious question — if attention does the real work, do we need the recurrence at all? The paper was called "Attention Is All You Need." The answer was no.

7. The Transformer — 2017 → LLMs

LSTM—sequential, can't parallelise→Transformer

The idea

Delete the loop. Let every position look directly at every other position, all at once. No walking through time — one big matrix multiply.

How it works — attention in one sentence

Every word emits three vectors: a Query ("what am I looking for?"), a Key ("what do I offer?") and a Value ("what I'll pass on"). Every query is scored against every key; high score = high relevance; the scores become softmax weights that mix the values.

Attention(Q, K, V) = softmax( Q @ K.T / √d ) @ V

That's it. Look at what's in there: a matrix multiply, a softmax, a scale. You wrote a softmax in Part 3 of your notebook. You already know every operation in that line.

What else is in the block (all of it familiar)

  • Positional encoding — attention alone is order-blind (it sees a set, not a sequence), so position gets added to each word's vector. Order is restored as data, not as architecture.
  • Multi-head attention — run attention several times in parallel with different weights. One head tracks grammar, another tracks reference. Same idea as a CNN's many kernels: several detectors, one layer.
  • Skip connections + LayerNorm — ResNet's +x, right here, wrapped around every block.
  • A feed-forward MLP — the network from your notebook, applied at each position. It's still in there.
The payoff of having built the MLP by hand. A Transformer block = your MLP + softmax + skip connections + a smarter wiring scheme. There is no new learning machinery after 1986: still forward pass, still cross-entropy, still backprop, still gradient descent. An LLM is this block stacked ~100 times and trained on a very large amount of text to predict the next token. That is the whole path from your notebook to ChatGPT — and you can now name every piece.

✗ The wall (current, unsolved): attention costs O(n²)

Every token attends to every token, so a 1,000-token input needs 1,000,000 scores; 100,000 tokens needs 10 billion. Cost grows with the square of the sequence. That's why context windows are finite, metered, and expensive.

Transformers are also data-hungry (they have less built-in structure than a CNN, so they must learn from examples what a CNN gets for free) and expensive to train. Active work: FlashAttention, sparse and linear attention, state-space models like Mamba. This chain isn't finished — you're joining a story still being written.

How to check it — metrics

Rule zero: a metric with no baseline is not a result. "97% accuracy" is meaningless until you know what logistic regression scores. In your notebook the NN got 96.4% — impressive until you saw logistic regression at 95.6%, at which point the honest summary is "+0.8% for 100× the complexity." Always compute the baseline first.

Precision vs recall — the trade-off is a dial, not a fact

Your model outputs a probability; you pick the cutoff. Lower it → more "yes" calls → recall up, precision down. Raise it → the reverse. The threshold is a business decision, not a modelling one. Cancer screening: crank recall, accept false alarms — a false positive costs a follow-up scan, a false negative costs a life. Spam: protect precision — a caught spam is worth less than a lost job offer. The default of 0.5 is a convention, not a recommendation.

Tune against the test set and you're overfitting to it by hand — your reported score becomes fiction. This is why your notebook keeps them apart, and why Kaggle hides the leaderboard test labels from you. The discipline exists because everybody, including you, will cheat accidentally otherwise.

What else moves the result — the factors

Architecture gets the headlines. In practice these decide whether your model works, and they're ordered here by how much they'll actually bite you.

1. Learning rate — the most important number in deep learning

How to find it

Start at 3e-4 for Adam, 0.1 for SGD+momentum. Try powers of 10 (1e-1, 1e-2, 1e-3…) and watch the loss curve for the first ~20 epochs — you're looking for the largest lr that still falls smoothly. Then add a schedule: start high to cover ground, decay later to settle into the minimum (CosineAnnealingLR, ReduceLROnPlateau). Big steps to arrive, small steps to land.

2. Input scaling — non-negotiable

Your digits: X / 16. Mixed tabular data: StandardScaler. Images: divide by 255, often then normalise per channel.

Why NNs care and trees don't: a tree only asks is x > 3.5? — the scale is irrelevant to a comparison. A NN multiplies inputs by weights and sums them. Feed it a feature ranging 0–100,000 next to one ranging 0–1 and the first swamps the gradient entirely; the second may as well not exist.

The one rule people break: fit the scaler on train only, then apply it to test. Fitting on everything leaks test statistics into training — your score inflates and you won't know why the model disappoints in production. You have pipeline_leakage_demo.py in this folder; it's the same trap.

4. The rest, ranked by how much they matter

Optimiser

Adam (lr≈3e-4) adapts the step size per weight — converges fast, forgives a bad lr guess, and is the right default. SGD + momentum is fussier but often generalises slightly better; it's what wins image benchmarks. Start with Adam. Plain SGD is a teaching tool, not a choice.

Batch size

32–256 typical. Small = noisy gradients, which is mildly regularising and often generalises better. Large = smoother and faster per epoch, but needs a higher lr and can converge to worse minima. Change batch size and your lr changes too — they're coupled, which surprises everyone once.

Activation

ReLU unless you have a reason. Never sigmoid/tanh in hidden layers of a deep net — their derivative maxes at 0.25, which is the vanishing-gradient chart above. GELU/SiLU are marginal improvements used in Transformers. Sigmoid still belongs on a binary output.

Depth & width

More capacity helps until it doesn't. Your Part 11 sweep, measured: hidden=2 → 27% (a real bottleneck), 32 → 96.9%, 128 → 96.9%, identical. Past the point where the problem is solved, extra capacity buys nothing and costs time. Bigger is not better.

Initialisation

He for ReLU, Xavier/Glorot for tanh. PyTorch defaults are already sensible, so you'll rarely set this by hand — but know it exists, because "loss is stuck at exactly log(C) from step 1" is usually an init or scaling bug, not a learning-rate one.

Data quality & quantity

The factor that dominates all the others. Doubling clean data beats every hyperparameter you will ever tune. Mislabelled rows put a hard ceiling on accuracy that no architecture can lift. Time spent on your data outperforms time spent on your model, nearly always.

Debugging order when a net won't train. Work down this list — it's roughly ordered by probability: (1) is the loss curve flat, spiky, or nan? → learning rate. (2) did you scale the inputs? → you didn't. (3) can it overfit 10 samples to ~100%? If not, the bug is in your code, not your hyperparameters — this is the single best test and almost nobody runs it. (4) do the shapes match at every layer? (5) is the loss ≈ log(C) at step 0? If not, init or output layer is wrong. (6) only now consider architecture.

The four things worth carrying out of this page

  1. Depth buys shapes. Stacked simple boundaries compose into complex ones. That's the whole reason for "deep" learning, and it's the XOR picture.
  2. Structure beats tuning. The CNN didn't win by tuning an MLP harder — it won by wiring in a fact about images (nearby pixels relate). Encode what you know about your data into the architecture.
  3. Give gradients a road with no tolls. ResNet's +x, the LSTM's cell state and attention's one-hop path are the same idea three times: don't make the gradient survive a long multiplicative chain.
  4. "Possible" ≠ "trainable". A one-layer MLP can approximate anything, and a 56-layer CNN can simulate a 20-layer one. Neither fact helped. Optimisation, not expressiveness, is what actually limits you — every model on this page exists because of that gap.

Where to go next

Do the CNN. You've got the theory now; the felt experience is what's missing. On Kaggle Digit Recognizer, run your MLP (~97%), then the same data through a small CNN (~99%). That 2% is Section 3 of this page becoming real: same data, same optimiser, better wiring.

Then CIFAR-10, where an MLP falls apart completely and a CNN is mandatory — that's where you feel why architecture matters rather than reading about it. After that, transfer learning (take a pretrained ResNet, retrain the last layer — most real vision work is this), and then attention.
